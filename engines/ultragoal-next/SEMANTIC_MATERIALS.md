# Canonical semantic materials, development version 3 (probe rubric version 4)

A semantic judgment concerns the meaning of supplied materials for the original
requirement. Native authenticity, current identities, execution, permission,
adoption and calibration remain separate admission questions. A reported outcome
can be internally supportive without becoming an authenticated observation.
Neither a clause list nor a declared material contract may weaken the original
requirement.

`ultragoal-semantic-context/3` adds a `material_contract` and requires each evidence
item to name its declared `material_type` and `version`. All IDs are unique in
their own collection. Evidence links must name existing clauses; conditions must
name existing evidence. Extra authority fields and unsupported role/type pairs
are rejected before provider dispatch. An explicit-dependency world must link a
condition to a supplied dependency inventory; its completeness is still assessed,
not established by the label. Version 2 remains declared-data compatibility.

The question distinguishes behavior descriptions from reported outcomes,
verification design from reported verification, cross-surface comparison,
proposed actions from reported recovery, and finding usefulness from finding
applicability. A useful lead can identify an investigation without certifying an
old conclusion or waiving a required verifier.

Supported material kinds include source code, patches, interface contracts, test
source, execution reports, documents, findings, action proposals, dependency
inventories and selection reports. Role/type/version are declared metadata, not
native authority. A test body cannot become an execution report through a tag.
Unknown definitions or required links remain missing support; they do not alone
prove a concrete conflict.

The two fixed probes separately ask about concrete conflict and complete supplied
support. Both original distributions are retained. A concrete conflict remains a
concern when another required surface is absent. Simultaneous valid conflict and
complete-support answers expose `conflicting-valid-probes` for review; there is
no fabricated combined probability. All version-3 rules are still uncalibrated
advisory.

Current development evidence: 27 prospectively authored synthetic comparisons,
with original labels and request hashes frozen before calls. The first run matched
24 labels and disagreed on three. Those are development observations, not a held-out
accuracy estimate. A blind reviewer is assessing material interpretation and
ambiguity before comparing outcomes. No result has been relabelled or promoted.

Example schemas and negative boundaries are executable in
`tests/semantic_materials.py`; production endpoints are `SEMANTIC_CONTEXT`,
`SEMANTIC_PROBES` and `SEMANTIC_DECISION`. Seven integrated material-schema/interpretation boundary tests pass, and an actual
internal CLI request retains version3/source bindings while leaving the mandatory
report unresolved. These are implementation tests, not semantic calibration.

Blind development adjudication was frozen before comparing outcomes. It agreed
with 26 of the 27 original author labels; the provider matched 23 blind labels.
The different judgment concerns whether an explicitly unrelated supplied finding
is contradicted as useful or merely lacks support. Returned-old-bytes recovery
must not be described as a successful committed save or durable disk preservation.
New fixtures clarify those surfaces and state helper/notation assumptions. The
original 27 cases and all labels/responses remain unchanged. Schema validity
establishes neither required-role coverage nor version correspondence, helper
meaning, inventory exhaustiveness or native authenticity.

A separate five-case prospective clarification run matched four labels. The
unknown-helper assertion case still produced a false concrete-conflict judgment
under the blind interpretation. This demonstrated limitation remains open;
verification-design is not qualified for consequential intervention. Clarified
requests/results are separate from the original batch, including the formerly
verbose or ambiguous representations. No probability threshold was weakened.

Rubric version 4, its threshold policy and the frozen calibration outcome are described in SEMANTIC_CONTRACT.md. Version-4 semantic results remain advisory.
