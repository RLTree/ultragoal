# Command reference

Resolve the installed plugin's absolute `bin/ultragoal` path. `help` and `inspect` report supported surfaces without provider calls or writes.

## Contract and checks

A UTF-8 contract begins with `UG<TAB>1`. Each `O` row has eleven tab-separated fields: `O`, stable ID, revision, exact statement, origin, selector, projection, rule, argument, required assurance, `mandatory`. Escape percent/tab/newline/carriage return as `%25`, `%09`, `%0A`, `%0D`. Keep the original acceptance statement and its source; this file alone does not establish protected adoption.

Selectors: exact relative path, `file:path`, `prefix:path`, or `*`. Projections: `membership`, `content`, `unknown`. Content-consuming rules cannot claim membership-only dependencies. Assurance: `exact`, `semantic`, `runtime`, `formal`; never choose a weaker assurance to make a report pass.

Run `check --root DIR --contract FILE --no-cache`; add a truthful `--disclosure synthetic|public|project` when selected semantic evidence already has disclosure authority. The installed narrow Keychain route is then used by default. Use `--local` to disable provider calls when disclosure is unavailable or explicitly undesired; semantic obligations remain unresolved. Optional `--baseline FILE` refuses silently removed or changed baseline obligations. `--cache DIR` uses an explicitly named directory outside the source root for advisory comparisons; it does not turn mutable disk results into proof. With `--disclosure`, the same directory keeps each validated semantic response under the digest of its exact request bytes; a later check with an identical request (same requirement, probe version and evidence bytes) revalidates that stored response with current Bend policy and reports it as `reused-prior` without a new provider call, while changed obligations are sent again. `--semantic` asks every semantic obligation afresh. `--details` includes facts and full local metadata. `--brief` returns only each obligation's `id` and `state`, plus `next_action`, `counterexample` and `chunk_coverage` for obligations that are not verified, the input problem count with the first ten paths, and the coverage totals; the exit code is unchanged. `--events` adds compact stage events to stderr. `--journal FILE` explicitly creates a reported operation journal; `explain --journal FILE` exposes conflicts and terminal state without replaying effects.

Rules include `member`, `path-member`, `absent-path`, `contains`, `absent-text`, `json-syntax`, the `fact-*` predicates below, `native`, and `semantic`. Literal and lexical predicates mean exactly their declared surface. A syntax pass cannot prove tests or runtime behavior. Unsupported dependencies remain unresolved.

Fact predicates hold when some selected file has a matching fact. Line facts compare the argument with one whole original source line, including indentation:
- `fact-definition`: a line starting (after indentation) with `def `, `class `, `fn `, `pub fn `, `function ` or `export function `, in Python, Rust or ECMAScript sources. Argument example: `def round_money(value, places=2):`.
- `fact-import`: a line starting with `import `, `from `, `use ` or `mod `, or containing `require(` or `import(`. Argument example: `import pathlib`.
- `fact-import-member`: a supported Python `from` import binds the named member under its required local name. Argument format is `module|member|local-name`, for example `xml.sax.saxutils|XMLGenerator|XMLGenerator`. A different module, alias or quoted/commented text does not satisfy it; unsupported import syntax remains unknown.
- `fact-heading`: a Markdown line starting with `#`. Argument example: `## Install`.
- `fact-json-key`: a key of the top-level JSON object; the argument is the decoded key, for example `request_timeout_seconds`. Nested keys are not facts.
- `fact-json-valid`: at least one selected JSON file parses; empty argument. Use `json-syntax` to require every selected file to parse.

A selected file in a grammar the rule does not support leaves the obligation unresolved, so scope fact rules to the files they describe.

A failed `absent-text`, `absent-path` or `json-syntax` obligation carries `counterexample`: the offending file with the smallest path, and for `absent-text` the line where the text first starts. Its `next_action` names that location. Other selected files may also hold the text, so rerun the check after each repair.

## Fit and host effects

`fit --root DIR --contract REQUIREMENTS.tsv` validates explicit requirements and
prepares exact forward/rollback patches. Existing requirements cannot be silently
removed or revised; such proposals emit no patch. No-follow captures keep linked
or unavailable targets unresolved. The native host owns any application and must
revalidate root/target preconditions; the inverse patch must not erase later user
edits. Without `--contract`, the result is only a manifest-derived template.
Neither proposal nor stored report grants permission or protected adoption.

## Facts and selection

Redirect `index --root DIR --scope SELECTOR --no-cache` to an index JSON file. Indexing returns optional facts, not verified project requirements. Large indexes use bounded capture/parse batches and exact source byte ranges instead of copying all source text. The report is written while indexing runs: `fact_sets` comes first, one file per line (`grep '"path":"src/a.py"'` finds one), then the other fields. A set has `path`, `content_sha256`, `grammar`, `representation`, `computation`, `key`, `coverage`, `facts` and `line_runs`. A fact is `[kind, value or null, line, start, end]`, with byte offsets; line `0` marks metadata without a source span. Plain line facts use `line_runs` (`[first line, start byte, length, ...]`). If indexing fails after some sets were written, the JSON ends with `state` `unknown` and no complete manifest, so `select` refuses it. `select --root DIR --report INDEX.json --query TEXT` streams the index, freshly checks source identities and returns original excerpts, retained anchors and named omissions; `--details` exposes candidate metadata. Ranking is file-first BM25F over path, definitions and body, then best-window reranking and reciprocal-rank fusion. The first 4G files are pooled, and the first G distinct groups are kept; G defaults to 128 and `--shortlist N` accepts 1 to 512. Bend combines global corpus statistics across input pages before ranking, so page boundaries cannot change IDF or ties. Bend compares all remaining candidate rows against the selected representatives in separate alias pages: duplicate excerpts share a group only when exact bytes and grammar match. The report retains all original aliases and anchors. Jev sees each representative excerpt and at most 16 displayed duplicate paths; unshown aliases remain unassessed by Jev but recoverable in the report. `measurements.ranking` names the physical pages and work. With explicit disclosure, shortlist groups are judged in head-plus-slices windows; a missing accepted judgment stays unassessed. A prior `--prior` selection is reported advice and cannot clear a current obligation.

## Native and semantic surfaces

`verify --rust FILE`, `--python FILE`, `--typescript FILE`, and `--stdin-c FILE` inspect captured syntax without running source. `--tools FILE` names the Python, Node and TypeScript module locations as a JSON object (`python`, `node`, `typescript`); without it the defaults are `/usr/bin/python3` and the Homebrew Node and TypeScript paths, and an absent tool is reported with the path looked up. Each observation hashes the tool and module it ran. C preprocessing and unsupported tool layouts are refused. `verify --bend-proof FILE --root DIR` checks the supported local import/law closure without execution; remote, unsafe, foreign and incomplete closures remain unsupported. Fixed captured-input subprocesses carry a current request/observation binding, current-source comparison and terminal/stream completeness. This is local bridge provenance, not protected host authentication. `explain --report` treats saved observations and results as reported data; it does not rerun or readmit them. These routes do not qualify arbitrary project runtime, host permissions or adoption.

Provider calls require explicit `--disclosure synthetic`, `public`, or `project`. These record the caller's already-authorized evidence class; they grant no new permission. Use minimal related evidence, never unrelated private data, credentials or raw personal histories. A live TypeSafe/Jev call uses the installed host's existing `research-run.typesafe` Keychain service by default; `TYPESAFE_API_KEY` or `--keychain-service NAME` may select an alternate authorized credential route. `--local` disables provider use. The credential never belongs in argv, reports or files. Files whose names routinely hold credentials (for example `.netrc`, `.npmrc`, `kubeconfig`, `*.tfstate`, service-account JSON, env files) and content with credential shapes (private-key headers, AWS, GitHub, Slack and Stripe keys, JWTs, credential assignments) are never disclosed, and the whole request body is screened again before dispatch. The [semantic contract](semantic-contract.md) specifies six explicit targets, two separate probes, raw-response validation and the fitted decision policy. Semantic results are advisory with one exception: a contradiction under the fitted policy, in a family that qualified on held-out data (currently `recovery-state`), fails an obligation whose admitted state is otherwise `unknown`. `--semantic-blocking off` keeps every semantic result advisory; the default is `on`. Legacy `recovery` requires explicit migration to its intended target. `semantic --request REQUEST.json --response RESPONSE.json` validates preserved bytes offline, with no credential lookup or provider call.

## Useful advice during work

`advise --request CONTEXT.json --disclosure CLASS` prioritizes useful work without executing it. The context has `purpose`, `question`, `observations`, and a `candidates` array; optional `subject` supplies material type/version/scope facts. Purposes are `test-choice`, `diagnosis`, `requirement-map`, `change-impact`, and `reuse`. Large request files are screened as one logical source through Bend pages before JSON decode; a late credential refuses the whole disclosure. Candidate descriptions and source excerpts are data, not new instructions. Supply concrete observations and competing alternatives rather than asking the model to restate an error.

Bend supplies target-specific Noul usefulness propositions, with a five-level Score rubric for requirement coverage. It owns both global order and final rank; probabilities, scores and confidence retain their distinct meanings. Advice planning uses batches of at most 256 with global candidate IDs; order and rank rows cross the core in ordered pages when needed. Candidates are ranked by question/observation word overlap and judged in windows: the top-ranked head in the first request, then slices of at most 8 questions with the head repeated as context. Every provider request stays within 64,000 bytes and 32,000 bytes for the state plus its longest question. Each request has its own deadline, 3,000 ms by default (`--semantic-deadline-ms`, 500-15,000), and at most two run at once by default (`--semantic-concurrency`, 1-4); Bend refuses values outside those provider envelopes. `check` sends one request per semantic obligation; an explicit `--semantic-max-requests N` (1-4,096) names every obligation not sent. Each candidate is judged once; one without accepted judgment is `uninspected` with its reason. Every candidate, typed distribution and attempt remains visible. `--usage-ledger FILE` appends a unique reservation before dispatch and a matching settlement afterward, including unknown usage when a timed-out call may have been billed. No spend cap is imposed. Scores order optional work; they do not grant permission, certify freshness or remove mandatory checks.

Exit codes: 0 requested local surface completed; 1 failed predicate; 2 unresolved evidence; 3 malformed input/tool boundary; 130 cancellation. A failure also prints `error: <code>` on stderr and `error_code` in the JSON, one of `invalid_arguments`, `deadline_exceeded` (a core request passed its own deadline; the message names the phase and request), `cancelled`, `credential_refused`, `disclosure_refused`, `resource_bound`, `input_changed`, `session_unavailable`, `core_unavailable`, `input_unavailable`, `invalid_input` or `operation_failed`. `indexed` and advisory semantic support are not task completion. Preserve original obligations and continue independent authorized work while a named gap is unresolved.
