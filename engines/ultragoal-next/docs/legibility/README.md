# UltraGoal legibility inventory

This registry names current source, commands, Cargo dependencies and four reviewed host boundaries. It is an enforcement input, not an approval of other raw effects or an all-language pass. `check_ownership.py` runs the project-owned, pinned standalone structural analyzer from sibling `engines/ultragoal-legibility`; the required Next gate builds and tests that analyzer offline. It does not require or install the retired EJ plugin. Preserve the analyzer's raw failures separately from this project's bounded ownership verdict.

`Root::stream_source` owns descriptor-bound source pages; its returned identity, digest and byte count are checked by callers before Bend admits the logical file. `resources::measure` reports host headroom or a closed observation error; it does not grant memory allocation. Private `provider/credential.rs::key` owns the optional credential environment and Keychain fallback. Its `keychain_key` is the only direct security command; it validates returned bytes, requires complete process output, and returns fixed errors without secret text. No key bytes enter command arguments or reports.

The direct dependencies are pinned from Cargo.toml with current owners and upstream references. Narrow structural profiles cover reviewed headroom, source hashing, selected provider declarations and JSON emission. The separate exact `material-ownership.json` contract classifies current production uses and must reject new sites; its effect/caller/outcome rows are reviewed for the exact current source and invalidate on source or test changes. The analyzer source, lock, fixtures, qualified macOS ARM64 binary and compiler identity are pinned in `engines/ultragoal-legibility/UPSTREAM_PROVENANCE.json`, whose digest is bound into `check_ownership.py`. Missing or changed tool inputs fail closed. Bend and Python use native proof and runtime suites; this Rust semantic checker cannot certify them. The obsolete source-root `ug-core` and Ruff cache were preserved outside the engine under owner evidence before removing them from the authored input set. `source_inventory.py` is shared by build/package and retains build-generated `Identity.bend` and `src/native_identity.rs` as bound inputs.

Current project ownership check: 96 exact material sites, including direct
native FFI, Unix socket and the actual `serde_json::to_writer` hash sink;
285 exact pinned dependency uses; eight privileged caller rules; every Rust
source byte bound for review; and one indirect ordered-index callback. The
disposable controls in `tests/ownership_negative.py` exercise new and
same-kind effects, unprofiled libc/network calls, skipped validation, removed
or non-test evidence, missing gate invocations, canonical local/qualified/alias
callers, stale Cargo and unparsed source. Evidence references resolve to real
Rust or Python tests or a directly executed script entrypoint. The shared
source walker excludes only configured root build caches and Python bytecode
caches; authored nested `target` modules remain bound, and a Rust module
explicitly crossing into an excluded cache is rejected. Rust path attributes
and include macros are read as tokens; comments, strings and character literals
are inert, while lifetimes remain syntax. Literal inputs are required in the
authored inventory; computed inputs fail closed until an actual generator and
its inputs are declared. The green
project check is bounded to these reviewed surfaces. EJ's method and function
pointer graph is incomplete; the private screened provider handle and native
session/credential tests cover the changed high-consequence routes. The check
does not prove call dominance, arbitrary new languages or protected host truth.
