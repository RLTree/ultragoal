# Core Beliefs

- This product surface exists to help users do real work, not to decorate the
  repo.
- Trust comes from visible state, provenance, reversible actions, and receipts.
- UI changes need runtime or browser-visible proof, not only static screenshots
  or schema checks.
- Accessibility, keyboard behavior, reduced motion, and high-contrast states
  are first-class states.
- Repeated design debt becomes an indexed task or a failing check.
