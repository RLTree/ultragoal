# Harness Ultragoal Gold-Standard Stack Developer Experience and Governance Proposal

**Document type:** research-backed, stack-specific engineering law proposal  
**Target system:** Harness Ultragoal and similar agentic software-governance products  
**Date basis:** July 1, 2026  
**Core thesis:** the harness is the product; the language stack exists to make the harness truthful, fast, observable, restartable, and mechanically governed.

---

# 0. Governing premise

The gold-standard stack is not “frontend + backend + database.” The correct unit for agentic software is:

```text
agent-legible repository
+ isolated execution harnesses
+ deterministic validation
+ repair/eval loops
+ high-cardinality observability
+ mechanically enforced architecture
+ production SRE discipline
+ governed cleanup of every artifact surface
```

Harness Ultragoal must treat every stack component as a **governed proof surface**. Rust, TypeScript, Python, PostgreSQL, ClickHouse, OpenTelemetry, Nix, Bazel, OpenTofu, Kubernetes, Codex, Agents SDK, and MCP tools are not a pile of tools. They are a claim-governance substrate.

The central law remains:

> **No claim exists until the Harness Ultragoal CLI can bind it to typed, current, same-surface evidence.**

A tool may observe. A package may build. A UI may render. A DB migration may run. A test may pass. None of those facts becomes a completion, product, release, or `update_goal` claim until `ultragoal` parses the result, binds it to the relevant proof surface and subject digests, verifies freshness, computes the claim ceiling, and emits a receipt.

# 2. Classification vocabulary

Every tool, concept, and practice is classified exactly once.

| Classification | Meaning |
|---|---|
| **REQUIRED** | Part of the Harness Ultragoal gold-standard stack. A repo using this stack must provide it, route it through the CLI, and bind its observations to receipts. |
| **DEFAULT_ON** | Enabled by default when safe and available. Absence must be explicit. Can support limited claims only when receipt-bound. |
| **GOVERNED_ADAPTER** | Supported and useful, but not canonical authority. Requires declared config, tool identity, input/output schemas, receipt fields, and claim-surface limits. |
| **OPTIONAL_LOCAL** | Permitted for personal productivity only. Cannot support claims. |
| **REJECT** | Should not be used for Harness Ultragoal work because it creates hidden state, weak proof, wrong abstraction, unnecessary risk, or product substitution. |

## 4.2 Repository law

`AGENTS.md` is a routing table. It must tell agents where to look and which commands are claim-bearing. It must not become an encyclopedia.

Required agent-readable sources of truth:

```text
AGENTS.md                       always-on work contract
ARCHITECTURE.md                 architecture map
docs/architecture/**            boundary law
docs/exec-plans/**              restartable contracts
docs/evals/**                   eval semantics
docs/telemetry/**               telemetry schema
docs/reliability/**             SLO and golden-signal law
docs/security/**                tool/secret/supply-chain law
.ultragoal/**                   law registry, receipt schemas, claim ceilings
```

Forbidden:

```text
hidden wiki-only architecture
Slack-only decisions
human memory as plan state
prompt-only law definitions
uncited model assumptions
untracked local scripts
```

## 5.1 Rust core/control-plane

### Classification

**REQUIRED**

### Purpose

Correctness-critical core for the CLI/control-plane, validators, receipt binding, claim ceiling, package inventory, parsers, workers, services, and performance-sensitive agents.

### Why it matters

Rust is the authority language for the enforcement engine. It gives strong static typing, explicit ownership, memory safety without tracing GC, high-performance CLIs, and a strong package/test/lint ecosystem. It is the right place for laws that must not be bypassed.

### Commands

```bash
ultragoal rust toolchain verify --emit-receipt
ultragoal rust fast
ultragoal rust standard
ultragoal rust release
ultragoal rust coverage prove --exact
ultragoal rust memory prove
ultragoal rust dependency audit
```

Underlying observations:

```bash
cargo metadata --format-version=1 --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features --locked --message-format=json -- -D warnings
cargo check --workspace --all-targets --all-features --locked --message-format=json
cargo nextest run --workspace --locked --profile standard
cargo llvm-cov --workspace --json --output-path target/llvm-cov.json
cargo deny check
cargo audit
cargo vet
```

### Config files

```text

Cargo.lock
.cargo/config.toml
.config/nextest.toml
deny.toml
supply-chain/audits.toml
.ultragoal/rust-policy.toml
```

### Install/bootstrap

```bash
rustup toolchain install 1.96.1
rustup component add rustfmt clippy llvm-tools-preview
cargo install --locked cargo-nextest cargo-llvm-cov cargo-deny cargo-audit cargo-vet
```

### Clean-checkout behavior

A fresh checkout must be able to run:

```bash
ultragoal bootstrap
ultragoal rust standard
```

without editor state, warm target dir, global `RUSTC_WRAPPER`, local cargo aliases, or undocumented scripts.

### Offline behavior

Allowed only with declared cargo registry/git cache manifest and locked dependencies. Offline success supports **OfflineRustBuildObservation**, not release truth by itself.

### Machine-readable output

Use Cargo JSON messages, nextest JSON/JUnit, llvm-cov JSON, cargo metadata JSON, and Ultragoal receipt schemas.

### Cache/resource behavior

Incremental compilation and sccache are allowed for fast loops. Clean proof must isolate `CARGO_HOME`, `CARGO_TARGET_DIR`, and `RUSTC_WRAPPER`, and may set `CARGO_INCREMENTAL=0`.

### Cleanup

Rust artifacts must be classed:

```text

CoverageArtifact
RustBuildLog
```

Use:

```bash

```

### Failure modes and remediation

| Failure | Agent-remediating output |
|---|---|
| Typecheck failure | rustc JSON span, crate, feature set, target, repair class. |
| Namespace violation | expected maximally factored path and move plan. |

**97/100.** Rust remains the best enforcement-engine substrate. Risk is mostly integration complexity and treating Rust-only proof as product proof.

# 11. Product laws for the full stack

## 11.1 Product Fitness

A full-stack feature is Product Fitness compliant only if the intended user problem is proven on the correct runtime surface.

Examples:

```text
API behavior proven through runtime API request/response
UI behavior proven through browser journey
agent cockpit behavior proven through trace/eval/run scenario
DB behavior proven through migration + runtime persistence journey
workflow behavior proven through durable replay/idempotency scenario
observability behavior proven through emitted trace/log/metric query
```

Invalid substitutes:

```text
Rust tests pass
TypeScript typecheck passes
Bun build succeeds
Postgres migration runs
ClickHouse table exists
Kubernetes rollout succeeded
agent says it is done
```

## 11.2 Product Cohesion

Product Cohesion requires the change to fit architecture, module boundaries, telemetry schema, DB truth model, UI framework boundaries, package surfaces, docs, and operational model.

Violations:

```text
UI imports DB code
Python eval mutates production DB
cache used as truth
ClickHouse used as transactional product state
MCP tool bypasses approval policy
agent trace lacks run_id
new dependency lacks owner/threat note
new prompt lacks eval coverage
```

## 11.3 Product Success

Product Success requires same-surface proof that the actual user outcome works.

For this stack, a Product Success packet usually needs:

```text
runtime API proof
browser journey proof
DB persistence proof
workflow completion proof if async
trace/event proof
SLO/golden-signal non-regression observation
accessibility proof for user-facing UI
security/secret boundary proof
```

# 16. Final proposed law text: Gold-Standard Stack Developer Experience

## HU-STACK-001: Agent-First Harness Law

The repository, runtime harness, validation system, observability stack, eval suite, and artifact cleanup system are first-class product surfaces. Language tools serve the harness; they do not define compliance.

## HU-STACK-002: Cross-Language Claim Authority Law

Rust, TypeScript, Python, SQL, infrastructure, telemetry, and agent tools may emit observations. Only `ultragoal` may convert observations into claims.

## HU-STACK-003: Clean-Checkout Discoverability Law

A fresh agent must be able to discover setup, validation, local runtime, evals, and release proof from repo files only. Hidden local state cannot support claims.

## HU-STACK-004: Same-Surface Full-Stack Proof Law

A claim about a surface must be proven on that surface:

```text
source claim -> source scan/typecheck
package claim -> package inventory
install claim -> clean install tree
runtime API claim -> runtime API proof
browser claim -> browser journey
DB claim -> database migration/query proof
workflow claim -> workflow scenario/replay proof
observability claim -> emitted/queryable telemetry proof
product claim -> user outcome proof
```

## HU-STACK-005: Lockfile Sovereignty Law

`Cargo.lock`, `bun.lock`, `uv.lock`, `flake.lock`, and provider locks are governed truth surfaces. Lock drift blocks dependency, build, package, release, and update_goal claims.

## HU-STACK-006: Telemetry Schema Law

No trace, metric, log, event, or eval record may introduce unregistered attributes. Every attribute has type, owner, cardinality class, privacy class, and allowed surfaces.

## HU-STACK-007: Agent Tool Boundary Law

Every tool/MCP action requires typed schemas, risk class, approval policy, idempotency class, telemetry, and cleanup. Tool use without policy cannot support claims.

# AGENTS.md — Harness Ultragoal Gold-Standard Stack Laws

This file is the Codex-facing law contract for repos using the Harness Ultragoal gold-standard stack.

These rules are not suggestions. They govern all Rust, TypeScript, Python, database, telemetry, agent, infrastructure, package, install, cache, runtime, product, release, and `update_goal` work.

---

# 1. Prime directive

Harness Ultragoal is a claim-governance product.

You may edit files. You may run tools. You may inspect logs. You may repair failures. You may not claim completion, review readiness, package readiness, install readiness, runtime success, product success, release readiness, or `update_goal` eligibility unless the `ultragoal` CLI verifies current same-surface evidence and emits/validates receipts.

Raw tool output is observation. `ultragoal` receipts are claim evidence.

---

Rust 1.96.1                 correctness-critical core, CLI, validators, services

# 4. Claim law

Never say:

```text
done
complete
ready for review
ready to package
release ready
product ready
product success
fixed
implemented
safe to update_goal
```

unless `ultragoal claim ceiling` permits that exact claim.

Allowed lower-claim language:

```text
I changed the source and have not yet minted proof.
The fast loop passed, but this does not support release readiness.
The standard loop failed on HU-STACK-006; here is the repair class.
The release claim is blocked by stale browser and database receipts.
```

# 5. Same-surface proof law

A claim about a surface must be proven on that same surface.

| Claim | Required proof | Invalid substitute |
|---|---|---|
| Rust source compliant | Rust source/typecheck/law receipts | package exists |
| UI works | browser journey/visual/a11y receipts | TypeScript typecheck |
| DB migration safe | empty DB + fixture DB migration receipts | SQL file exists |
| Cache works | cache-surface receipt | DB tests |
| Event bus works | NATS stream/replay/consumer receipt | service unit tests |
| Workflow works | Restate/Temporal scenario/replay receipt | worker compiled |
| Observability works | emitted/queryable trace/log/metric receipt | code contains tracing calls |
| Product Success | same-surface user journey receipt | tests pass |
| Release Ready | full final packet | reviewer approval |

# 6. Rust laws

Rust remains the authority language for correctness-critical code.

Required commands through Ultragoal:

```bash
ultragoal rust fast
ultragoal rust standard
ultragoal rust release
ultragoal rust coverage prove --exact
ultragoal rust memory prove
ultragoal rust dependency audit
```

Required rules:

```text
- Cargo is substrate; Ultragoal is authority.
- rust-toolchain.toml and Cargo.lock are required.
- rustfmt, clippy, cargo-nextest, cargo-llvm-cov, cargo-deny, cargo-audit, cargo-vet are governed.
- Repo-owned Rust source must use a maximally factored module tree.
- No residual prefix encoding.
- No generic utils/common/shared/misc buckets unless a governed class makes them concrete.
- No implementation-history filenames like wave82, temp, old, final2, hack.
- No raw serde_json::Value authority.
- Parse external input into typed authority.
- Rust memory discipline uses ownership, RAII, bounded caches, bounded queues, cancellation, and cleanup. No tracing GC architecture.
```
