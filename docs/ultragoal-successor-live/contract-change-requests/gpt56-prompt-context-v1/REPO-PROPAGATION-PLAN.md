## H. Prompt and context evaluations

Evaluation-owned surfaces: HCT-EVAL tasks, scorer audits, failure harvesting, research promotion, quality-in-use journeys

Use the same outcome contract across exposed configurations where possible. Do not write one prompt to flatter each model and then call the model comparison causal.

Representative task groups:

1. typed transform: extract and reconcile manifest/registry rows with unknown-data handling;
2. routine engineering: reproduce and fix a bounded regression with focused verification;
3. deep judgment: falsify a claim or diagnose a multi-causal failure;
4. parallel orchestration: allocate three independent nodes, handle a blocked dependency, review, recover, and integrate;
5. fresh-user routing: select the right canonical skill and complete the intended journey;
6. adversarial: stale evidence, prompt-inferred configuration, ambiguous route, scope escape, hidden write, reward-shaped receipt, and first-material-defect stop.

Measure:

- task success at the named behavior surface;
- routing and authority correctness;
- false-pass and unsafe-effect rate;
- context bytes/rows loaded and irrelevant-context ratio;
- model/tool calls, elapsed time, and cost where exposed;
- review defects found before integration;
- fresh-user and maintainer comprehension;
- unsupported claims and calibration.

Promotion requires representative improvement, guarded non-regression, independent review, bounded rollback, and exact runtime metadata provenance. Static prompt assessment alone cannot promote the change.
