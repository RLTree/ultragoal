# Root Review Entry Point

This directory is an integration-ready, non-authoritative contract change request produced from a source-level review of the current Harness Ultragoal prompt and context topology.

It does not edit or supersede the adopted successor contract. The Ultra root remains the only owner that may accept any part of it, change manifests or registries, reconcile shared authority, update claims, or declare node/release/completion state.

## Decisive design changes

- Preserve one lean outcome contract across supported model configurations.
- Route context by active node and stable ID instead of loading all registries at startup.
- Keep static agents role-only and supply exact typed task envelopes at invocation.
- Allocate substantial dependency-closed node packages, with one implementation lane per node.
- Stop rolling review after the first decisive material defect; reserve comprehensive review for its named claim boundary.
- Preserve read-only candidate review while using separate ephemeral scratch-only executors for reproducible builds and tests.
- Generate minimal compatibility prompts and retire them only under migration proof.
- Validate prompt/task/context semantics and representative behavior, not non-empty prose or digests alone.
- Bind every scoped candidate change to one exact same-session canonical write-scope row and root-only authority row; treat its paths as instruction-only `propose_write`; reject undelegated, Git, host, shared-root, hardlink, alias, symlink, special-file, and cross-device hazards; require a separate root-owned effect mediator for any actual write; and bind runtime roles to typed root-owned receipts.
- Commit the complete closed envelope, except its derived `context_id`, into that context identity; constrain repository result targets to exact delegated generated outputs and scratch targets to exact bounded scratch grants so evidence, ceilings, effects, verification, and output obligations cannot be substituted.
- Fail every scoped external effect closed unless its effect and single-use approval resolve exactly once in the same session from immutable rows under the protected root-owned `root-decisions/effect-authority` namespace. Open each authority source descriptor-first without following links; require one repository-device, single-link, bounded regular file; bind device, inode, mode, link count, size, timestamps, content, provider, action, kind, target, effect identity, approval link/status/validity/usage, source and row digests; reject aliases, replacements, extra or substituted rows; and reopen and revalidate the same path/object identity at session end. Approval time must additionally resolve through a single-use root-issued receipt under `effect-authority/session-receipts`, bound to repository, pre-context candidate ID, authority session, envelope capture time, effect-source set, nonce, and bounded skew. Envelope validation never authorizes execution. Before any effect/session validation, capability mint, replay lookup, or consumption, the mediator must descriptor-open the supplied root as an existing canonical directory without following the final name, reject missing, non-directory, special, symlink, lexical, or physical aliases, bind its device/inode/type plus internally derived URI and digest, and require both caller candidate fields to match exactly. The initial mediator retains that open root descriptor; final mediation revalidates it, independently reopens the supplied path, and requires both descriptors and the path to name the exact initial root object before reading effect or session authority. Moving the original root and replacing its path therefore fails even when original authority leaves are moved into the replacement, and failure consumes neither capability nor authorization. One separately adopted mediator instance must itself execute the complete initial validation before internally minting an opaque, non-constructible, non-cloneable, non-serializable capability whose object identity and private state bind that exact result, repository root object, candidate, authority sessions, effect-source set, receipt, and trusted time. Only the same mediator may accept that exact object during final revalidation, enforce monotonic time and a five-minute lifetime, and recheck receipt and approval expiry. Immediately before a possible external call, the mediator factory's shared private registry atomically rejects or consumes the complete protected approval-identity set plus session-receipt identity, then consumes the token; every mediator from that factory consults the same registry, and a failed final check consumes nothing. Replay decisions use internally derived immutable repository-and-protected-namespace tombstones for each `approval_id` and `receipt_id`; caller repository fields and mutable nonce, session, source, row, candidate, context, time, status, or value bindings remain validation or detailed audit inputs but can never partition replay identity or revive a consumed stable ID. Reissue therefore requires a new stable ID, while independently canonicalized repository roots prevent unrelated repositories from overconsuming each other. There is no caller-visible builder, registration method, or injectable ledger/state. Missing, fabricated, substituted, cross-mediator, stale, rolled-back, cloned, serialized, or reused capabilities and authorization identities fail closed. This Python proposal models single use only within one process; cross-process and restart durability remain unproved and adoption stays deferred pending a canonical durable root mediator. It has neither a live trusted receipt nor an adopted mediator clock and executes no external effect.

## Required root disposition

Return one of:

- `ACCEPT`: independently review, apply the selected exact changes, update all affected manifests/digests/projections, and reopen invalidated evidence;
- `REWORK`: record one decisive material defect and issue a corrective scope;
- `REJECT`: identify the conflicting adopted law or current evidence;
- `DEFER`: name the dependency or external authority that prevents a safe decision.

No file in this directory raises a claim ceiling or proves implementation, model/runtime configuration, installation, discovery, product behavior, readiness, release, node closure, or goal completion.
