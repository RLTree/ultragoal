# Goal Run

Keep one outcome, existing plan and integration owner. Use this workflow for
substantial dependencies, useful delegation or recovery; ordinary self-contained
implementation does not need a queue or runtime startup sequence.

Resolve the next dependency from current inputs, user constraints, relevant dirty
state and acceptance evidence. Reuse valid completed work. Execute within scope
and verify at the user's or dependent system's boundary. Preserve follow-on
requirements through steering; finish the remaining authorized outcome.

Use runtime context, capabilities, inventory, findings or claim reads only when
the next typed operation needs them. Revalidate its exact target, candidate,
inputs and authority before effects. A failed prerequisite blocks dependent
operations; do not probe sibling commands against that same unchanged failure.
Continue independent native work under its own authority, without claiming the
blocked runtime executed it. Planning and inspection have zero hidden writes.

## Coordination

Handle sequential dependencies directly. Delegate substantial independent work
when quality or elapsed-time gains justify its cost; reserve integration capacity.
Give workers bounded deliverables, disjoint write ownership and acceptance checks.
Keep shared manifests, authority and integration with one root. Preserve others'
changes. Use existing leases and `WorkerResult-v1` only where the actual typed
worker protocol requires them; do not invent a parallel lease system.

Reconcile exact outputs before dependent execution. Worker summaries are evidence,
not authority or acceptance. Use independent review for material trust-boundary
changes or uncertain acceptance; another round must resolve a distinct risk.
Run required checks and relevant failure paths, then stop unless new evidence
justifies more. Do not stage, reset, stash, commit or publish to simplify custody.

## Failure and recovery

Preserve completed outputs and unique uncommitted state. Distinguish product,
agent, environment and provider failures. After two unchanged failures, change
the hypothesis or stop that path. No paid retry or duplicate effect without
applicable authority and custody.

On cancellation, stop dispatch, cancel owned in-flight work through its supported
mechanism and reconcile observed effects. Silence is not evidence of no effect.
After interruption, reopen the checkpoint and refresh changed target, candidate,
authority and input evidence. Classify work as completed, reviewable, in-flight,
unstarted, stale or ambiguous. Resume only the authorized dependency-legal
remainder; never replay completed effects.

Validate identity, evidence and conflict rules before selection or reuse. An
unsafe newer event cannot replace trusted state; conflicting completion evidence,
ambiguous ownership or a partial effect holds dependent work for supported recovery.
Preserve exact deterministic path, cancellation, idempotency and recovery guards.

Keep checkpoints to the remaining outcome, owner, candidate, accepted outputs,
preserved changes, open failure and next action. Invalidate only work dependent
on changed assumptions. Do not copy transcripts or create receipts of receipts.

Report the useful result, verification, remaining requirement and actual authority
boundary. Claim goal-state changes only after observing the corresponding operation.
Unknown cost remains unknown. Native work, typed runtime and installed-product
acceptance are separate evidence surfaces.
