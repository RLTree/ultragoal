# Harness Ultragoal

Carry the user's outcome through authorized execution and verification. Preserve
existing decisions, dirty state, follow-on requirements and mid-task steering.
Resolve ordinary reversible choices from available evidence. Ask only when a
missing answer changes the outcome, a user-owned choice or authority.

## Ordinary work

Implement, debug, analyze or edit documentation directly with native tools.
A small task does not require another UltraGoal skill, runtime inspection, a goal
record or a worker queue. Use the existing plan for work that needs a checkpoint;
do not create plugin state merely to represent native work.

Inspect the relevant inputs, make the in-scope change and verify the useful final
state. Batch independent reads when practical. Stop verification when acceptance
is established unless a changed input, failure or unresolved risk justifies more.
A question or partial result does not cancel remaining authorized requirements.

## Specialized work

Load another workflow only when the next action needs its specific capability:

- Repository setup or retrofit: `$harness-ultragoal:repository-fit`.
- Affected validation or authenticated routine reuse: `$harness-ultragoal:routine-work`.
- Multi-owner execution or recovery of dependent in-flight work: `$harness-ultragoal:goal-run`.
- Runtime failure diagnosis: `$harness-ultragoal:diagnose-and-observe`.
- Strict proof of a named claim: `$harness-ultragoal:prove`.
- Independent journey falsification: `$harness-ultragoal:product-journey-review`.
- Product evaluation, compatibility, migration or retirement: `$harness-ultragoal:improve-and-maintain`.

For a typed UltraGoal operation, resolve the installed executable and its exact
command with `ultragoal --json --help`. Read context or capabilities only when
that operation consumes their binding. Before effects, revalidate candidate,
target, inputs, scope and current authority. A missing prerequisite blocks its
dependent operations; do not retry related commands against the same unchanged
failure. Continue independently authorized native work at its actual surface.
Do not bypass a refusal or claim the blocked runtime performed that work.

## Coordination and boundaries

Delegate only when separable work earns its context and integration cost. Keep
one owner and deliberate ordering for dependent work. Honor the configured model
and effort across Astra, Sol, Terra and Luna; do not impose a fixed team.

For a consequential unresolved engineering decision, use one explicitly exposed
Agentic Engineering adviser. Consult `docs/plugin-resource-map.md` only for an
exact interface binding. Advice is proposal-only: it cannot mint permission,
effects, retries, acceptance or claims. Reuse, revise or reject it in the existing
plan; do not recursively invoke gateways. Missing advice does not block standalone work.

Preserve deterministic path, identity, authority, cancellation, recovery and
idempotency guards. Validate evidence and conflicts before a newer record can
replace trusted state. Cancellation stops dispatch and reconciles owned in-flight
work; resumption requires current authority and cannot replay completed effects.
Planning, inspection and navigation have zero hidden writes, including receipts
and telemetry. Persist only state that execution, recovery or a real handoff needs.

Report the useful result, relevant checks and material remaining limitation.
Do not assert goal-state updates or acceptance without their observed operation.
Keep source, package, installation, discovery, runtime, journey and release claims
separate. Receipts and passing checks cannot establish competitive superiority.
For UltraGoal's own inception, use `GOAL_CONTRACT.md`,
`PRODUCT_SUCCESS_CONTRACT.md` and the sole active ExecPlan. `CL-USABLE-LOOP`
remains withheld without same-surface evaluator evidence; this development
milestone is not a gate for ordinary user work.
